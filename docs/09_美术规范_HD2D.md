# 09 两种画风与 HD-2D 表现规范

版本 v3.1。本文是纯文字美术要求，不指定任何图片、网页画面、参考 HTML、已有角色像素阵列或照搬对象。原 v2 球面战斗光照规范已经撤销；不得重新要求完全复刻旧范例。世界观与物种沿用本套文档，不因改画风而更换游戏内容。

## 1. 两版共同的空间与构图

星球是实在的三维球体，可以全向旋转；战斗是独立的固定斜俯视场景。地面使用有厚度的方格地块，有少量水、树石和高台，前后遮挡、接触影、顶面与侧面明暗建立纵深。小妖、浊和植被使用二维美术层/精灵，不能通过把身体拼成三维球、胶囊、体素人来交差。

中心心和多方向入口是主要构图关系。玩家要读懂哪里可放、敌人从哪来、谁在出手、心是否危险。装饰围绕战斗阅读安排，不要用一圈障碍把自由场地夹成固定道路。树冠和前景不可挡住关键格子、心或角色脸部；必要时对遮挡物淡化。

两版使用同一地图、种子、角色身份、比例、站位、镜头、界面信息结构、时辰、动画事件时间和战斗数值。只有渲染笔触、轮廓、纹理、配色处理与特效形态不同；不得一版做完整游戏而另一版仅换皮静态棋盘。

## 2. 像素风

### 2.1 像素必须真实成立

世界默认在 480×270 的低分辨率帧缓冲绘制，再用最近邻整数倍放大；留边优于非整数拉伸。若窗口较小需缩放，明确标识非最佳预览尺寸。DPR 变化不能让像素宽度乱跳。系统文字可用独立清晰 UI 层，不下载字体。

地块顶面约 16×16 源像素，小妖幼形以 16×16 起步，复杂度确有需要可升为 24×24，但两版世界比例一致。像素簇表达明确的外轮廓、受光面、暗面和材质；草叶、石缝、树冠的颗粒有组织，不以随机彩点填满。描边与内部细节有节奏，避免所有东西都变成圆点或一色方块。

禁止先画高清光滑曲线再仅加 CSS pixelated 冒充像素；禁止模糊缩小的三维截图、抗锯齿曲线、连续渐变主导角色；禁止靠重景深、网点、噪声掩盖粗糙造型。

### 2.2 色彩与光

素材固有色使用下列 ENDESGA 32。清晰主体必须保有色块边界。光源、雾与轻微泛光可产生表外颜色，不要求最终整屏锁调色板。太阳从画面左上方来，地块顶面亮于侧面，角色脚下有接触影。夜景保留轮廓，不把可部署格和敌人压成黑色。

星球允许简单分档光照；不再强制旧 14 的四档明暗表和 Bayer 算法。浊染通过降低饱和度、偏灰蓝并保留明暗对比表达；浊本体可用紫色识别，不能把所有地面涂成紫路。净化按空间扩散恢复固有色，像素版可以用离散像素阈值过渡。

## 3. 彩色线条插画风

这不是黑白线稿，不是工程线框，不是“像素版外面加描边”，也不是逼真三维材质。主体用有分量的深色或同色系深色轮廓、清楚的彩色面、少量柔和插画阴影与高光。内线少而准确，用于表情、结构和动作，不把每一块地都描成同粗黑格。

轮廓可有轻微粗细变化，边缘干净，颜色温润，角色有表情与材质差异。线条版可用高分辨率程序路径生成二维纹理，再由 WebGL2 放入同一空间；这些路径和纹理必须由当前代码原创生成。UI 同样采用线条、色面和清晰字级，不复制其他样例的面板、标题或构图。

与像素版保持相同的属性色语义、浊与净化识别；允许在同一色系内使用柔和的明暗过渡，不需要把高清线条量化成锯齿。线粗、填色与阴影强度集中参数化，避免装饰线盖过战斗信息。

## 4. 原创角色与自然动作

### 4.1 形象边界

优先使用原有七只幼形：滴答（水/射）、苔团（苔/拦）、灯芯（暖/溅）、茶烟（汽/控）、萤子（光/射）、芽芽（苔/援）、瓢瓢（水/产）。依据名称、属性、定位及图鉴的文字设定设计原创剪影，不照抄旧字符画。滴答保留水滴记忆点，苔团保留苔质团簇，灯芯保留灯火身份；其余细节由实现者设计，不能把七只都画成换色团子。

不用附加的新物种替换这些伙伴，不把某个被提供过的美术样例整体搬入游戏。场景仍来自苔眠星的草地、林地、湖畔、山脚等地貌，不新增与原设定无关的主题竞技场。

### 4.2 动画要求

- 待机：呼吸是局部体块和表情变化；眨眼有不同相位，附属部件有轻微跟随。
- 出手：有朝向目标、蓄力/预备、释放、恢复四个可读节奏；弹道发射时刻与动作同步，不从无关部位冒出来。
- 移动：重心转移、落脚/漂移依据形态设计，脚下影子与高度一致；飞行与地面角色不能同一个跳跃模板。
- 受击：短反应和局部表情，不能整只长期闪白掩盖动作；睡着后闭眼、姿态放松，停止攻击；胜利有独立反馈。
- 像素版用明确的逐帧姿态，待机约 4–6 fps、出手约 8–12 fps；线条版可用局部关节/路径插值。两版事件时间相同，表现不必机械逐像素对应。
- 可派生眨眼、换色、发光遮罩和少量局部变形；不得只生成整图压扁、上移、翻转当全套动作。像素轮廓在动画中仍须稳定。

### 4.3 数据规范

精灵可用文本数据描述 id、尺寸、锚点、调色板映射、各动作帧/局部部件、帧时长、发射点、发光遮罩。像素帧以颜色索引表达，线条版以原创路径和局部动画参数表达；运行时生成纹理，不提供现成图片素材。旧 14 字段与范例不再强制兼容。程序需校验尺寸、帧时长、动作名和发射点，不能静默吞掉坏数据。

## 5. 特效与空间层次

水珠、火团、闪电、茶雾、治疗、产露等与小妖定位对应。像素版使用有结构的像素弹道/碎片，线条版使用简洁有轮廓的色面与柔光。特效只突出释放与命中，不持续铺满全场。射程、可放、不可放和路径提示是交互层，不常驻遮住材质。

净化由中心心向战场扩散，再回写星球对应区域。前后两场景同一地貌/时辰有连贯色彩。转场可短暂拉近、淡出/离散化再显露沙盘，但不要求复刻旧原型时序。

## 6. UI 与信息层级

主体优先级：心与入口威胁 → 角色/敌人及攻击 → 交互提示 → 地形 → 装饰 → 背景。两版布局相同而视觉语言分别统一；像素面板使用整齐的色块与边缘，线条面板使用轮廓与色面。系统字体足够清楚即可，不能下载外部字体。

## 7. 验收与美术未决项

使用实际游戏比例观察，不能只拿放大单角色作为成功依据。七种定位、敌我、可放格、高差、入口方向必须可读；没有美术素材依赖，不能有占位圆点、默认图形或过度滤镜。自然动作和构图需要设计者最终判断，本文件不声称既有实现已达到标准。

最终造型、线粗、装饰量、昼夜光照强弱仍属创作选择。先按以上约束完成自洽的原创方案，不援引任何过去失败画面的布局和素材作为正确答案。画面参数统一放入 VISUAL_PARAMS，默认值见 16。
