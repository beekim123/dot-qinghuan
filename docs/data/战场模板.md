# 自由方格战场数据规范

版本 v3.1，方案 A。替换旧 v3 的七个固定道路模板和预览。这里没有图片、地图字符画范例或强制照搬的布局；保留地貌家族与数据含义。

## 1. 模板职责

模板只定义地形、地块高度、中心心、边界入口、露眼候选与障碍。模板不保存道路序列，不存在 `#` 路格，也不存在“路格只能放拦”的标记。敌人动态路径由运行时寻路产生。

| 字段 | 含义 |
|---|---|
| id / family / seed | 编号、地貌家族、确定性生成种子 |
| size | 默认 [11,7]；后续首领 [13,8] |
| terrain / height | 每格地形及 0–2 的高度级，每级半格 |
| heart | 中心格；默认 11×7 时为 (5,3) |
| entrances | 不同方向的边界入口列表，当前原型默认三个 |
| obstacles | 明确占格的树石等，禁止覆盖心、入口和露眼 |
| dew_candidates | 至少两个候选格；一处较安全、一处较接近来敌区域 |
| decor | 非占格的草簇等；不得改变寻路或挡住 UI |

坐标 `(x,y)` 从 0 起。普通草地、林地、沙地可部署/可通行；浅水仅水属性可部署且地面浊不可通行；深水不可部署/通行；高台可部署但地面浊不可攀爬；心和入口不可部署。地形战斗数值见 04。

## 2. 自由布局与寻路校验

1. 中心心周围留有布阵空间；入口分布于不同边界方向，不做左进右出的强制通道。
2. 空场时每个入口必须能通过四邻接到达心。障碍疏密形成选择，不能把所有入口都夹进唯一蛇形走廊。
3. 每次放置/移动/收回/睡着/唤醒或地形变化后更新寻路；新增阻挡导致某入口或活敌无路时拒绝该操作。先校验再扣露水，失败不可吃掉资源。
4. 无路拒绝规则和拦截规则完全按 04 第 2.3 节，不额外实现“堵死后敌人穿墙”的兜底。
5. 路径由 BFS/A* 计算，选择相同长度路径时采用固定邻接顺序；从一格到下一格插值移动。
6. 布阵提示显示当前预测路径，可以改变阵型观察路线变化。提示不是固定路面纹理。
7. 检查尺寸、坐标界限、重复占格、连通性、心居中、入口分散、露眼合法及前景遮挡。

## 3. 地貌家族

沿用 03 的优先级：泉口/星心（后续）→ 雪坡 → 湖畔 → 山脚 → 林间 → 沙岸 → 草原。湖畔增加浅水但留多种通行选择；山脚用少量高台；林间用稀疏占格树和非占格植被；沙岸使用沙地减速。地貌变化不允许改回固定道路。

本次原型只需一个可读、完整、原创的草地/林间自由战场配置，同一个配置用于两种画风。可复用确定性布局生成，但不能自动生成大量无人检查的模板充数。完整游戏原计划 30 个模板是后续内容目标，不是本次工作量。

## 4. 与星球关联

落点的地貌、时辰、种子传给战场。转场进出必须保留 nodeId，以便真实胜利只净化对应区域。两风格的同种子/同节点须产生相同障碍、露眼、入口和单位初始状态；不得用两张不同地图比较美术。
