# 16 完整双画风 HTML 原型规格

版本 v3.1 纯文字需求。完全替换原球面战斗版 16；原 H1–H6、多页图鉴编辑器和强制复刻精灵不生效。先按本文完成可比较的两种画风，不转做 Godot，不扩成正式游戏。

## 0. 任务与硬边界

### 0.1 任务

为《清欢小星》制作两个完整的 HTML：pixel.html 与 line.html。两者都是“360° 星球选地 → 转场 → 独立 HD-2D 自由方格布阵 → 自动守心 → 真实胜败 → 结算 → 回星继续或重试”的可玩原型。完整指这个循环，不是正式游戏全部系统。

画风必须原创。仅用本包文字，不找图、不加载旧参考 HTML、不复用过去被否定的画面或角色像素数据；不照搬任何参考作品的场景、物种、道具、UI 或布局。保留本项目名称、世界设定、物种、核心规则。只改画风，不改游戏。

### 0.2 硬规则

1. 原生 WebGL2 绘制世界画面，不用 Three.js、Pixi、游戏引擎或任何外部库。Canvas 2D 可用于程序生成纹理，DOM 可用于界面。
2. 完全离线；无联网、CDN、外部图片/模型/字体/音频资源，文字用系统字体。不生成图片文件作为交付素材；美术由原创代码/文本数据在运行时生成。
3. 两个 HTML 各自自包含：内嵌普通 JS、数据和 GLSL 字符串，单独复制任意一个也可双击以 file:// 打开。禁止 fetch、XMLHttpRequest、ES module、动态 import 或依赖服务器。若开发期拆为 .js，交付前内联，不能牺牲独立打开。
4. 世界渲染与战斗模拟分层；两版使用同一逻辑与确定性数据快照，仅表现层不同。
5. 画面参数统一进入 VISUAL_PARAMS；玩法初值另放 GAME_PARAMS，不能混成难以追踪的魔法数字。未知细节选最简单做法并记 DECISIONS.md，不擅自扩大范围。
6. 不把旧 14 的四档光照、Bayer、旧明暗表、五个精灵范例和字段名当作当前硬规则。像素固有色用 09 的 ENDESGA 32；空间、线条与动画按 09。
7. 原型默认静音，不做音频；不安装/更新 Godot，不触碰用户本地电脑。本次只在授权云端目录创建新原型。

## 1. 两版共同内容

- 苔眠星：362 格（含 12 个五边格）的三维区域球体，地形、浊、清亮状态、候选守心落点；可全向旋转、有限缩放、定位所选落点。
- 至少三个候选落点，能通过旋转查看不同朝向；调试用固定节点应包含背面及极区可检查的位置。正式选择仅允许可见标记命中，列表可先定位后确认。
- 一个精心完成的自由方格战场：默认 11×7，中心心，三个不同方向的边界入口，少量障碍、高台、露眼；不是固定路线。
- 原有小妖幼形：滴答、苔团、灯芯、茶烟、萤子、芽芽、瓢瓢。初始免费部署三只，备战可增援；不做成形/灵形、育种、图鉴编辑器或新物种。
- 敌人：浊团、灰絮、大浊；三波真实守心。浊化小妖、结缘战、泉主/星心战只属于后续完整游戏，不要求本次实现。
- 布阵：选择/拖放、合法性、射程、收回、换位、开始；战斗：暂停、1×/2×、露水增援、唤醒、灯照；波间暂停与下一波预告。
- 白天和夜间可切换以比较材质和光源；两版相同开局时辰。不要求完整天气系统、浊潮、每日挑战、整局剧情、小院或局外养成。

七只伙伴不必同时初始上阵；角色数不是让画面挤满的理由。原型数值以 04 定位模板和图鉴为初值。萤子普攻跳跃、芽芽治疗、瓢瓢产露须表现出定位差异，不能全部变成同一种弹丸换颜色。

## 2. 状态与进度

唯一正常流程：PLANET → TRANSITION_IN → DEPLOY → BATTLE ↔ WAVE_PAUSE → RESULT → TRANSITION_OUT → PLANET。暂停不推进模拟；结果状态不能继续生成敌人、攻击或扣血。

每场记录 runSeed、nodeId、battleSeed、进入前的心灯/露水/净化集合快照、当前波次、队伍及占格。星球与战场不是两份互不相干的假数据。

- 胜利：全部三波生成完、无存活敌人、心灯 > 0。展示真实战斗统计、心灯和露水收支。确认回星时对该 nodeId 结算一次，净化中心周围三圈内的有效陆地格，更新清亮度并标记节点完成；不能重复点结算刷奖励。
- 失败：心灯 ≤ 0，立即终止模拟、展示失败原因。不给净化或胜利奖励。可“重试本节点”（恢复开战前快照与种子，清空本次战斗临时状态）或“回星”（保留此前已净化进度；心灯归零时显示重新开始本轮的入口，不伪装正常继续）。
- 新一轮：明确按钮，重置本轮星球和进度；保留旧轮状态不是必需。
- 最少保证同一次页面会话内回星再进入时进度保留。可用 localStorage 作为便利，但 file:// 下失败时退回内存并提示；不得把存储异常变成白屏。跨 HTML 的存档无需共享，相同 seed 和命令可复现即可。

“重试”是原型比较便利，不宣称它是完整肉鸽最终存档规则。结算不做假结缘弹窗和无效卡牌；当前不实现的按钮不要出现为可点击入口。

## 3. 星球交互

使用轨迹球/四元数实现无极区死角的全向旋转；不能只绕竖轴转，也不能把俯仰夹角限制到无法看到极点。区分短点击和拖动；拖动不误触进入节点。射线拾取考虑球体遮挡，不点穿背面。节点选中态、地貌、难度初值与进入按钮清楚。旋转不重抽种子、不丢掉清亮格。

进入时围绕所选节点拉近并切入独立战场，不继续把单位贴在球面。回星恢复原星球、选中节点及附近视角，能直接看到对应区域的变化。

## 4. 自由方格守心战

执行 04 第 2 节及 data/战场模板：可部署位置由地形、占格和连通性决定，所有定位均有自由选择；敌人基于当前阻挡四邻接 BFS/A* 寻路到中心心；阵型变更影响路线；封死任一入口或活敌路径的操作先拒绝再说明，不扣资源。

拦在邻接范围截停有限数量的地面敌人，飞行不受拦截；远程按射程与选目标规则自动攻击。固定 30 Hz 模拟，帧率不影响伤害/产露/波次；2× 仅加速模拟；暂停时允许合法操作。技能必须有费用、冷却、效果和反馈。正常胜败来自模拟，调试强制结束若存在须明确标“调试”，不能作为验收证据。

战场固定斜俯视，保持全场可读，允许有限缩放及复位但不旋转。布阵、战斗、结算保持同一构图，避免换镜头掩盖问题。

## 5. 双风格比较

pixel.html：有意组织的像素簇、低分辨率画布、最近邻、有限固有色、清楚的明暗面与地块厚度。角色必须像真正像素美术，不是光滑三维图加像素化滤镜。

line.html：彩色、明显轮廓、清晰形状、柔和插画阴影、少量局部细节；不是黑白线框，也不是像素图外加黑边。二维角色由程序路径/局部动作生成；地形仍有空间层次。

两版的节点、布局、人物身份、大小、机位、UI 信息、数值、战斗波次与动作事件时间一致。输出相同测试种子和部署说明供手动比较；只有美术处理可以不同。具体要求见 09。

## 6. 统一参数

下表是本原型默认，不是最终画面批准。旧 16 参数已被替换，不要求读旧文件。所有新视觉常量须归入 VISUAL_PARAMS 对应分组并说明用途；可按 P 打开简洁参数面板，至少能改光强、线粗/像素比例、特效强度并恢复默认，不做大型编辑器。

| 参数路径 | 默认 | 含义 |
|---|---|---|
| version | 3.1 | 原型参数版本 |
| render.pixelWidth / pixelHeight | 480 / 270 | 像素版世界内部大小 |
| render.pixelFilter | nearest | 像素纹理采样 |
| camera.planetFovDeg | 20 | 星球窄视角 |
| camera.battleFovDeg / battlePitchDeg | 30 / 40 | 两版相同战斗机位 |
| camera.battleZoomMin / battleZoomMax | 0.85 / 1.2 | 战斗缩放范围 |
| camera.dragRadPerPx | 0.006 | 星球拖动敏感度 |
| camera.idleSpinRadPerSec | 0.05 | 可关闭的空闲自转 |
| camera.recenterSec | 0.8 | 定位所选节点时长 |
| terrain.heightStep | 0.5 | 一格为单位的高度级差 |
| sprite.basePixels / pixelsPerTile | 16 / 16 | 像素角色及纹理基准 |
| light.sunDirection | [-0.55,0.6,0.58] | 左上来光，使用前归一化 |
| light.dayAmbient / nightAmbient | 0.75 / 0.30 | 原型环境光初值 |
| light.heartRadius / lanternRadius | 2 / 3 | 光源半径（格） |
| line.outlineWidthPx | 2 | 960×540 UI 比例下的基准线宽 |
| line.shadowOpacity | 0.22 | 插画暗面初值 |
| post.bloomStrength / vignetteStrength | 0.15 / 0.08 | 轻后期，主体不糊 |
| timing.transitionInSec / transitionOutSec | 1.2 / 1.2 | 转场初值 |
| timing.purifySec | 3 | 净化动画时长 |
| fx.intensity | 1 | 特效强度 |

当前 GAME_PARAMS 默认：boardSize=[11,7]、heartCell=[5,3]、entranceCount=3、heartHP=12、startDew=6、initialDeployCap=3、waveCount=3、fixedHz=30。其他数值优先沿用 04；冲突或缺项写 DECISIONS.md。不以“调美术”为由私改另一版数值。

## 7. 实施顺序

一次完成，不需要逐阶段向用户等批准：
1. 阅读文档、写清默认决定，建立同内容数据及共享状态逻辑；
2. 完成星球旋转/拾取、独立自由棋盘与寻路；
3. 完成真实布阵到胜败回星的闭环；
4. 分别完成原创像素、线条两套美术和自然动作，不只套颜色；
5. 离线与功能测试、画面自检、整理最终文件。

不能先做很大展厅，再把主流程当以后补做。

## 8. 自检

- 断网、file://、任一个 HTML 单独打开，不依赖其他文件、无网络请求、无控制台错误。
- 星球拖动能检查背面和两极；点击不穿透；选中节点确实进入对应战场。
- 同一格合法性、资源扣除、换位、收回、入口到心路径一致；改变阵型会改变路径；封死拒绝并保留原状态。
- 空阵/薄弱阵容能真实失败，合理阵容能真实获胜；波间暂停、暂停不计时、1×/2×都可用。
- 净化、节点完成、清亮度只成功结算一次；失败不净化；重试快照正确；回星再进不丢已有进度。
- 两版相同 seed/命令产生相同事件序列和结果；美术差异不能改变碰撞、命中与时间。
- 像素轮廓稳定、色簇明确；线条彩色且有明暗层次；两版角色不是三维模型，动作不是整图抖动。

只记录真实执行过的浏览器、条件、结果；未运行项写“未验证”。没有浏览器能力时不能声称截图验收/通过，也不能用伪造日志冒充运行。本文与本交接包不附任何图片参考；测试报告以文字说明。

## 9. 最终交付

在新的独立目录交付 pixel.html、line.html、README.md、DECISIONS.md、TEST_REPORT.md。两个 HTML 可分别直接打开，README 写清控件、同种子比较办法、已验证和未验证项。不含图片/字体/音频素材、参考 HTML、旧原型文件、安装包和 node_modules。

## 10. 设计者打开后看什么

1. 打开 pixel.html：转完整颗星球、看背面和两极、选节点进入。
2. 在固定斜俯视沙盘自由摆小妖，观察合法格、中心心、多入口和随阵型变化的路线。
3. 开战看每只小妖的动作与出手节奏、不同定位、敌人路径和战斗清晰度；试暂停和 2×。
4. 分别完成胜利与失败，检查结算、回星净化和失败重试；不是只展示动画结尾。
5. 打开 line.html，使用同种子、同节点、同阵容与命令重复以上流程，对比轮廓、材质、动画和整体风格，而非两种不同内容。
6. 再决定采用哪种画风；尚未选择前不得把任一原型写成已获批准。
