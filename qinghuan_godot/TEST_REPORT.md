## 实际模拟观察

- 六次完整种子：`1, 7, 22, 83, 144, 20261022`，全部从无永久升级的初始三只开始，通过真正的 `BattleSim.step()` 战斗与成长，最终封三泉、洗净眠眠。
- 每次最短路线六场，模拟时间分别 **460.2 / 455.6 / 467.8 / 485.8 / 458.3 / 483.6 秒**。没有强制胜利按钮或倒计时通关。
- 六地貌×八种子的48场推荐开局均胜利，最少仍有18/18心灯。此版刻意宽容；这些样本不能推导所有阵型或种子的胜率。
- 同种子、同三只1级伙伴，集中放在远离心的合法角落会在约77.35秒真实失败，心灯0/18；推荐阵型保住18/18，位置确有影响。
- 独立苔团会被真实侵蚀至睡眠，放开通路。未阻止的眠眠会动态走到心并造成失败，不会超时自动获胜。
- 同名传承：对应开局伙伴从2级开始。异种传承：第四只1级伙伴。新局地形和局内状态重新生成，永久数据保留。

## 实际图形检查

在云端原生桌面实际运行 **Godot 4.7.2 + OpenGL Compatibility / Mesa llvmpipe**，不是浏览器代替运行。

已实际操作并观察：小院出发、星球选点、独立沙盘、推荐布阵、真实出怪与波次、1×→2×→3×、首战18/18胜利、结缘茶烟、返回星球队伍增至四只、原伙伴升级、清亮0%→9%且对应土地改变。水平及垂直拖动能查看不同表面与标记，没有极区锁死。

初轮图形检查发现：操作条与伙伴卡片局部重叠、选中卡片调色影响头像、窄窗口七卡片溢出侧栏。均已修复：独立布局间距、仅选中边框、裁剪横向滚动伙伴栏；增加了自动布局断言。最终已重启最新代码，在1180×812原生窗口目视复核小院、地图与沙岸战斗：操作条与伙伴卡片有明确间距；选择滴答仍为蓝色；七张小院卡片被限制在世界侧，横向滚动可到瓢瓢，不覆盖右侧升级区；三人战斗卡片也不越界。再次实际点击推荐布阵、开始、调速、暂停，看到多向来浊和第二波。验证截图保存在交付工程之外的 `qinghuan-qa/final-yard.png`、`final-planet.png`、`final-battle.png`。

云端驱动曾报告 VSync 不支持与没有 ALSA 音频设备，Godot 回退 Dummy 音频；本项目无声音功能。最终用 `--audio-driver Dummy` 重启后，日志只余不支持VSync的驱动提示，无游戏脚本错误或音频设备错误。没有将这些环境提示当作游戏逻辑测试通过的替代证据。
