# 清欢小星｜场景构图与游戏 UI 重设计

**日期：2026-10-22 · 研究与设计稿，不是已实现效果。** 只写本设计目录，不修改 `qinghuan/` 或其文档。和美术方向「露光苔湾」配套；本稿解决画面组织、状态、信息和交互，不替代角色/环境原画。引擎沿用当前原生 Godot 项目；运行时仍为纯代码生成，无参考图、外部字体、音频或模型资产导入。

## 实现范围：以当前代码为准，不借重画改玩法

本稿已复核 `battle_sim.gd`、`run_state.gd`、`main.gd`。只改像素画面与信息呈现，不加入旧设计文档里尚未实现的系统：11×7战场、1×/2×/3×都可用、三波自动推进、空格开始/暂停、Q即时灯照、最多七个不同种类伙伴、现有三选一确定奖励和当前传承/永久升级原样保留。灯照当前为6露/18秒，不增加选格或二次确认；效果以代码为准（所有活敌伤害与减速、存活友方治疗，心是视觉起点）。文档04/11用于理解愿景，不能覆盖当前玩法。线框数值仅示例，正式UI必须绑定真实状态。

## 先说结论

推荐 **A「林湾环抱式 HUD」**：世界连续铺底，中央空场守心，四角是少量有具体用途的“小器物”，七位伙伴组成一条完整底部托盘。**不是把现在的面板换个位置，也不是把沙盘继续放大。** 应先分配心、三向入口、战斗动作、选择详情和七人操作所需的空间，再让林湾美术长在这些安全区之外。

玩家第一眼应看见“林湾中间一盏灯，伙伴围着它，浊从几个方向靠近”；第二眼才看到“我还有多少心灯、何时下一波、当前能做什么”。不要第一眼看见六个等权框和一大块棋盘。

## 1. 当前三张画面为什么仍然不像完成的游戏

以下是对实际截图的观察，不把已经取消的右栏当作唯一问题。

| 证据 | 实际问题 | 本次改变 |
|---|---|---|
| `final-battle.png` | 标题/副标题/分隔线、世界矩形、右侧长教程、下方三张等宽卡组成文章式栏目；战斗只有中间一幅配图 | 游戏名和宣传语退出战斗；规则变成按需交互反馈；场景不放在内容框里 |
| `forest-review-03.png` | 材质和角色已有变化，但绿面板、标题层级、心灯大条、介绍文本仍是信息页；同一个心灯状态重复占位 | 只保留一个全局心灯HUD；场内心只显示受威胁和受击反馈，不再重复完整常驻数值 |
| `hud-battle-02.png` | 右栏虽移除，仍有完整矩形世界窗口；心灯、阶段、露水用同样的框同等强调；板面被放到几乎没有呼吸空间 | 世界/气氛连续；心灯是独特重要形，阶段是轻量短签，资源和技能合组，不复用同等大框 |
| 同上 | 底部左边三人小岛、右边两个纵向操作按钮、再右边孤立灯照，视线跳三次；设计并未证明容纳七人 | 底部为完整七人选择带；自动布阵在左侧辅操作；右下是一个完整“露水→技能”因果组 |
| 同上 | 入口紫标很弱，树大且密，单位集中在心周围；自由空格边界并不清楚 | 入口使用场景锚定短签和朝心的短箭头；树群偏置；“拿起伙伴时”才清晰显示全体合法方格 |
| 同上 | 选择了伙伴，但屏幕缺少眼前操作的清楚代价/结果；常驻一句操作说明不能取代情境反馈 | 显示当前可执行动作、露水花费、地形和封路原因；取消/确认在状态里明确 |

不是“非矩形就像游戏”。规则一致的矩形也能服务游戏；真正要去掉的是**文章式容器、同权信息、与场内决策脱节、仅按三人演示铺出来的布局**。

## 2. 已核对的真实参考：借原则，不借素材

五组来源，全部是一手官方商店、开发者日志或任天堂官方手册。截图已下载到本目录 `references/` 供研究，**不得进入游戏资源或运行时依赖**。没有把玩家评测当作官方设计意图。

### R1 — Into the Breach：威胁信息属于棋盘
- [官方 Steam 页面与截图](https://store.steampowered.com/app/590380/Into_the_Breach/)；补充 [任天堂官方页面](https://www.nintendo.com/us/store/products/into-the-breach-switch/)。已观察 `590380-0.jpg`：全局电网在左上，当前目标右上，选中对象/地形靠角落，攻击箭头与受影响格在世界内。官方说明明确强调敌方攻击预告。
- **采用：** 先让威胁位置与结果可读，再把细节解释放到角落。入口预告、睡着、有效相邻、格子合法性都应贴着事件。
- **不采用：** 军用仪表审美、密集描边、永久棋盘、回合制整屏目标列表；本作是自动战斗，不能承诺“每一招未来路径完全确定”。路径提示只表示当前占格下的预测，部署后重算。

### R2 — Isle of Arrows：阶段主动作不能淹没在帮助里
- [Gridpop 官方 Steam 页面与截图](https://store.steampowered.com/app/1946970/Isle_of_Arrows/)。已观察 `1946970-0.jpg`：顶部小资源簇、明确的 Start Wave、下方当前可放的牌、居中地图。
- **采用：** 布阵时只有一个明显主动作“开始守心”；自动波间只显示下一波预告，不加“下一波”确认按钮。当前可操作对象和费用在一起。
- **不采用：** 悬空等厚玩具底座、随机牌规则、固定道路、原游戏的卡框/塔/图标。它的道路机制尤其不能套到本作自由布阵。

### R3 — Thronefall：场景主次先于 HUD
- [Grizzly Games / Mythwright 官方 Steam 页面与截图](https://store.steampowered.com/app/2239150/Thronefall/)。已观察 `2239150-0.jpg`、`2239150-1.jpg`、`2239150-2.jpg`：大块低纹理地面容纳行军与战斗，外围地貌围出空间；局部生命与兵种信息贴对象，资源集中于角落。第一张是几乎无HUD的宣传截图，**不能据此推断实际游戏永不显示HUD**。
- **采用：** 用环境轮廓和密度留出可读战术空场；对象上才出现对象信息。小院的建筑升级入口依附建筑而不是总览仪表盘。
- **不采用：** 高饱和低多边形画风、骑士角色、它的固定建筑点与大规模 RTS 操作方式。

### R4 — Dorfromantik：开发者亲自移除“待办清单 UI”
- [Toukana 开发日志：UI Improvements](https://toukana.itch.io/dorfromantik-prototype/devlog/198346/devlogromantik-2-biomes-boats-and-more-big-news-soon)；[官方 press kit](https://www.toukana.com/dorfromantik/presskit)。日志明确说明从旧式 To-Dos 改成世界内任务提示，并整理右侧牌堆；已观察日志图片 `dorfromantik-ui.jpg`。
- **采用：** 把“哪个入口马上来浊”“哪个伙伴睡着”等可定位状态还给世界；不是把它们翻译成永久右侧任务清单。关键信息仍有可键盘/手柄访问的详细解释。
- **不采用：** 六角拼图规则或其米色圆角 UI；本作星球虽是六角球面，战场必须是自由方格。

### R5 — Super Mario Galaxy：先聚焦，再确认进入
- [任天堂官方说明书，印刷页5–7（PDF页3–4）](https://m1.nintendo.net/docvc/RVL/USA/RMGE/RMGE_E.pdf)；本地另存同一游戏欧洲官方手册，已查看其中“Galaxy Selection Screen”图示。
- **采用：** 系统可旋转、目标可聚焦、进入要明确确认；选择探索地点和正在战斗是两种界面状态。只显示当下有用信息，而不是把所有进度解释平铺。
- **不采用：** 星系轨道画法、角色、音效、星星造型或具体按钮皮肤；本作是一颗可全向旋转的六角星球，不改成平面关卡连线图。

> 以上“采用”是本次设计推论，不声称原作者为清欢小星背书。GDC讲稿检索到了条目但原链接当前转向维护页，因此不将其未读内容作为论据。

## 3. 方案 A：林湾环抱式 HUD（推荐）

### 3.1 全屏构图与共同皮肤

- 世界是“溪湾中的一片可操作空场”，不是摆在深蓝矩形里的一块展台。底层保留有厚度的方格与固定斜俯视；不因自然岸线牺牲多方向通路。
- 心在画面中部略上；边缘至少三入口错开朝向。中央及各入口到心之间的可操作格不放装饰遮挡。树群偏左后、低对比远林作气氛、右前少量水，是美术建议，不是指定固定敌路。
- 同美术使用 **“叶托与灯签”**：深苔灰底、暖米白系统字；小型托片只承载实际控件。稳定阶梯角、下沿暖土暗边；不做四面亮金描边、不为每行文字画面板。
- 暖金只给心灯/待确认主动作；露水青蓝；浊紫只给危险；选中用奶油实线+角标，不与危险混用。
- 图标和角色从项目原始代码绘制生成；托盘头像沿用世界精灵整数倍，不另做高精高清人像。
- 没有游戏名、品牌副标题、章节式分割线、常驻教学段落。场景名首次进入时短暂出现，之后可在暂停/帮助查看。

### 3.2 固定锚点（屏幕坐标，原点左上，单位px）

以下按**内容区**，不包含操作系统标题栏。矩形是布局/点击安全范围，不要求把每个矩形画成框。

| 元素 | 1440×900 | 1180×812 | 原则 |
|---|---|---|---|
| 世界 SubViewport 画面 | `(0,45,1440,810)` | `(14,82,1152,648)` | 480×270×3 / 384×216×3，nearest；绝不非整数拉伸 |
| 心灯 HUD | `(24,24,264,64)` | `(20,20,236,60)` | 图标+12/18或分段灯芯，不把当前值重复到另一栏 |
| 阶段短签 | `(576,28,288,44)` | `(452,24,276,44)` | 布阵/波次/暂停是状态，不是大标题 |
| “开始守心” | `(620,92,200,52)` | `(490,88,200,48)` | 只在初次布阵存在；战斗时此位置释放给视野 |
| 暂停/速度/小笺簇 | `(1160,24,256,56)` | `(940,20,220,56)` | 按钮各至少44px；速度不跟露水混排；1×/2×/3×保持现有全部可用 |
| 战术地面最大投影包络 | `(216,180,1008,546)` | `(188,190,810,444)` | 见下方四点多边形；不是外框，也不是等厚岛边 |
| 心位置目标 | `(720,453)` | `(593,412)` | 不会被上方阶段条或下方卡牌挡住 |
| 七人伙伴托盘 | `(280,764,808,112)` | `(212,692,708,100)` | 七张同时完整可见，不滚动，不只为三个初始伙伴设计 |
| 单个伙伴点击卡 | `104×96`，间隔8 | `88×84`，间隔10 | 托盘两侧16px，顶部8px；空位只画浅占位，不画伪可用人物 |
| 自动布阵/布局辅操作 | `(24,788,232,72)` | `(20,712,172,80)` | 只在初次布阵出现，战斗收起；层级低于开始守心 |
| 选中详情（临时） | `(24,584,240,156)` | `(20,528,224,144)` | 左下空场外；只出现一张，不顶开世界，不重复全人物档案 |
| 露水+载具技能合组 | `(1136,720,280,156)` | `(944,636,216,156)` | 露水余额在技能费用上方，两者保持紧邻；按钮不藏在选中卡里 |
| 短反馈/操作提示 | `(368,716,704,32)` | `(284,650,620,32)` | 需要时才出现一行，不能做常驻说明书 |

**投影四点安全包络：**
- 1440：`(600,180)→(1224,414)→(840,726)→(216,492)`。
- 1180：`(476,190)→(998,376)→(710,634)→(188,448)`。
- 地形实际可是不规则林湾，不能把这四点当四条崖壁。多边形外侧左下/右下自然留给情境卡和技能；入口标签只可压在其周围空隙，不压进底部托盘。
- 包络按当前全部11×7战场；首领战不自行扩成13×8。主体低于可辨尺寸时优先减少边缘装饰，不能让HUD盖住单位。

**显示预设决定（设计目标，尚未实机验证）：** 默认480×270，紧凑窗口使用384×216，两档均原生3×nearest；当前工程已有相应分档，不另向用户请求技术许可。紧凑档比480少20%宽高像素，必须单独验证最远格、角色表情、点选与视觉比例，不是把480纹理缩到1152。

**整数缩放与留边：** 1440高900并非16:9，上下45px；1180×812上下82px、左右14px。留边使用同一低对比气氛底色，并可放清晰HUD，但不复制/拉伸世界边缘。场景无视觉描边盒，UI独立原生分辨率。384预设必须重新fit镜头和点击映射，不能仅把480纹理缩到1152；点选先减viewport origin再除3。将源世界分辨率切换只当显示预设，不改变格数/寻路/技能半径。

### 3.3 七人托盘具体内容

- 每张只含：快捷键1–7、精灵、名字（2字）、职责形状；第二行是状态而不是每张重复“Lv.1”。
- 未出场显示“可部署”；备战显示“增援 4露”；已出场显示小位置标+“在场”；睡着显示闭眼形+“唤醒 4露”。等级/属性/详细数值移到选中卡。
- 选中卡升高4px（整体锚点不变）、奶油角标；在场角色同步脚下短环。键盘/手柄焦点与选中分开显示；不能只换底色。
- 托盘显示全队七只不等于七只都能开局免费部署。托盘上沿显示当前在场数/现有免费名额（读取free_cap），不写死“3/3”或添加“备战2”规则；未可用角色说明原因。
- 当前最多七个不同种类。不开第八槽、不加入重复种类、不加入资质或目标偏好编辑；托盘只表达现有队伍与战斗状态。


### 3.4 三种信息密度

| 状态 | 常驻 | 仅交互出现 | 必须隐藏 |
|---|---|---|---|
| **布阵，无选择** | 心灯、波次、开始、七人托盘、资源技能组、入口短预告、自动布阵 | 地形说明/伙伴详情/帮助 | 全体射程、全格高亮、全路线、露水收支表、全羁绊文字 |
| **布阵，拿起伙伴** | 上述骨架 | 所有合法空格的顶面细线；当前格合法性；本人的射程/有效四邻连线；当前预测通路；“放下/取消” | 与本次放置无关的其他人的射程；长段规则 |
| **进行中，无选择** | 心灯、当前波/剩余、暂停速度、露水技能、七人状态 | 被击中者短HP条、产露飘字、睡着提示、入口新批次警示 | 开始按钮、自动布阵、永久路径、格网、所有人的完整数值 |
| **进行中，有选择** | 同上 | 对象卡+可执行动作与费用、本人射程；鼠标进入可操作格后合法性 | 自动弹出的全档案、无关邻接效果 |
| **手动战术暂停** | 保留正常明亮世界、暂停短签、现有战术操作 | 选格网/路径/局部解释 | 全屏黑遮罩或大菜单占住棋盘 |
| **自动波间** | 保留战斗骨架，短暂显示下一波预告 | 当前选择详情 | 手动“下一波”按钮或新增自动暂停规则 |
| **玩法小笺** | 保留现有帮助入口 | 需要时查看规则 | 永久占据战场的教程全文 |

**暂停不是菜单。** 空格按现有行为开始/暂停，不把可读战场压暗。不额外加入Esc菜单、自动波间暂停或新的操作流程。

### 3.5 方格、路线、选择和费用

1. **普通观看：** 顶面材质/局部高度提供空间感，不画77格全亮棋盘。入口有短向内箭头+种类/数量短签，清楚显示来自至少三侧；不画永久紫路。
2. **拿起/拖动：** 所有合法空格显示细实线角框，非法悬停格显示虚线+原因图标及短句。合法与非法不只靠绿红；深水/树石/心/入口各有真实原因。可选“显示网格”快捷项应可重绑，不能抢走现有Tab调速。
3. **悬停：** 格边高亮与角色脚点严格对应，射程按真实规则绘制；高台、浅水适配等在临时卡里一句说明。当前预测路线使用短段灰白箭头，部署后立即重算，不冒充固定通路。
4. **会封死通路：** 留在拿起状态、原位置不丢、资源不扣；目标格标“会封死通路”，相关入口短闪框；不让角色先落下再弹回造成成功错觉。
5. **费用：** 下手前写“换位 2露”“唤醒 4露”“增援 4露”；余额不足显示“还差2露”，禁用但仍可看解释。不能等扣除时才首次告知。
6. **灯照技能：** 固定右下显示“Q 灯照 · 6露”，冷却数字绑定当前18秒计时。按Q/点击即按现有规则释放，不选目标、不增加确认步骤。帮助或悬停说明真实全场伤害/减速及治疗效果；心处演出只是视觉起点，不能让UI谎称只影响附近。布阵时写“开战后可用”；缺露/冷却显示真实原因，不能只发灰。

7. **收回/换位/唤醒/增援** 都走真实连通性检查；不通过时给相同风格的局部原因。所有反馈是玩法状态反映，不能为好看把路径固定下来。
8. **详情卡结构：** 名字+属性/职责 → 体力/当前状态 → 一句当前相邻或地形增益 → 1–2个当前合法操作。完整数值与说明进入现有详情；不新增资质/天赋/目标偏好系统。
9. **帮助：** 首次操作显示一行即时提示；“小笺”在帮助菜单，不占一块永久画面，也不拿诗句代替费用和规则。

## 4. 现有循环如何成为完整游戏界面

| 状态 | 主问题 | 推荐呈现（保留现有机制） |
|---|---|---|
| 小院 | 升什么、带谁出发？ | 星砂与当前传承常驻短信息；灯树承载oil/dew/bond三项升级；底部选择已解锁伙伴替换第三位；孔明灯承载开始新局 |
| 星球总览 | 去哪个候选点？ | 真三维球体、六角地貌、三口泉、候选锚点；底部短候选签，不常驻多张详情卡 |
| 星球聚焦 | 此点是什么、给什么？ | 一张临时详情卡+真实奖励和泉等级+确认；从背面候选聚焦，不能点击穿球 |
| 布阵/战斗/暂停 | 怎么守心、现在怎样干预？ | 方案A；三波自动推进，空格暂停，Q即时释放 |
| 战斗胜利 | 选哪一个现有奖励？ | 先看到净化，再三张互斥奖励卡：确定结缘或原有替代修习、补给、静心修习 |
| 行商/露泉 | 花露水/选哪种服务？ | 保留当前服务数据，场景物件加一张当前选项卡；不额外设计奇遇系统 |
| 回星 | 刚才净化在哪？ | 回到同一落点朝向，展示真实空间回写，再开放下一批候选 |
| 整局胜/败 | 带谁回家？ | 真实星砂、封泉、伙伴数；选一只当前队伍中的传承伙伴，回院。胜利不自行变两只 |

### 4.1 星球布局：球是主体，详情只服务当前选择

| 元素 | 1440×900 | 1180×812 |
|---|---|---|
| 总览球体 | 中心`(668,434)`、直径648 | 中心`(540,392)`、直径534 |
| 选中球体 | 中心`(552,434)`、直径648 | 中心`(444,392)`、直径534 |
| 临时详情卡 | `(1056,196,360,440)` | `(790,172,370,448)` |
| 进入按钮 | 卡底`312×56` | 卡底`322×52` |
| 普通候选3短签 | 总区`(348,782,744,80)` | 总区`(214,706,702,80)` |
| 解锁泉主候选 | 同一区域改6槽，每槽`116×80`，间8 | 同一区域改6槽，每槽`107×80`，间12 |

当前代码生成3普通候选并追加已解锁泉主，最多6个，不能硬锁三个。普通三候选时用大短签；最多六候选时短签只保留类型/编号/图标，详细风险与奖励归当前详情卡。无需滚动隐藏泉主。

正面候选绑定实际格，背面不穿球显示伪位置。底签可聚焦背面点；悬停不抢旋转，拖动不误进入。顶部只有心灯、日时/星相、露罐和三泉状态短印记。R仍定位当前选择。选点后球平移偏左，但保持可读体积；右卡是临时情境卡，不是所有页面必须有的侧栏。

未实现的预计敌数、夜战属性等不伪造预报；设计图上的数量属于版式占位。实现时只展示当前模型可可靠提供的数据。按当前候选类型显示守心、泉主、露泉、行商，不借旧文档额外加入结缘战/奇遇。

### 4.2 小院：把现有升级挂到世界里，不新增管理系统

- 灯树挂三条小枝，对应现有 **灯油oil / 晨露dew / 心意bond**。点其中一项才出费用卡；仍按当前等级上限3、费用35+等级×30星砂，不改规则。
- 果实卡写真实永久效果：心灯上限+2、每场露水+2、行商结缘减价。不可把文档里的“出阵上限+1”塞进当前树。
- 院中底部伙伴托盘仍只做已有的“替换第三位起始伙伴”；当前传承只展示/沿用，不新加拖动闲逛、窝管理、图鉴或多载具选择。
- 孔明灯或原有出发物件提供开始新局动作，不把“新局”藏成不可发现热点。可交互物件有悬停短签，默认不铺开升级列表。
- 这些是**现有动作的场景化入口提案**，不是声称现有物件已经可点；实现前仍需验证鼠标命中与遮挡。

### 4.3 奖励与局末

- 三选一保留现有确定结果；结缘是一个奖励选项，**没有概率、赠送或失败判定**。已集齐时按当前代码显示修习替代；不添加满八人替换流程。
- 1440三卡：`(264,260,288,340)`、`(576,260,288,340)`、`(888,260,288,340)`；1180三卡：`(134,228,288,332)`、`(446,228,288,332)`、`(758,228,288,332)`。背景保留刚刚净化的林湾，不插入额外结缘弹窗打断。
- 每卡一条效果与真实数量，选择后回星；不额外加一步“领取”制造重复点击。状态切换要防重复结算。
- 局末先短演出，接真实统计与**选择一只**传承伙伴；结束屏不加不存在的成就、剧情解锁、羁绊结算或第二只传承。

## 6. 可验收标准（下一步实机必须同时满足）

### 构图/像素
- [ ] 实机内容区1440×900与1180×812分别截图；不是把大图缩放成小图。世界是480×270×3或384×216×3，nearest，每个源像素宽高均3屏幕像素，HUD文字独立清晰。
- [ ] 所有当前11×7场全部交互格、心、至少三侧入口完整可见；HUD不盖任何关键角色脸/脚点。四边有呼吸空间，不是把板面再塞大。
- [ ] 同一镜头开关HUD时，仍然是一幅有环境层次的完整游戏场景，不是卡片中贴一张图。
- [ ] 新画面去掉标题副标题、永久教程、统一亮框和长资源表；又没有因“极简”删除暂停、速度、技能/费用和七人状态。

### 战术可用性
- [ ] 七只伙伴一次可见；已出阵/备战/睡着/不可部署各有形状+文字区分；预算/出阵上限真实。
- [ ] 无选择时无永久格网/紫色路；拿起任意职责伙伴时全体合法格可辨，不出现“拦只能放某行/射只能路边”的假限制。
- [ ] 任选左、右、上/下不同方向入口，能在3秒内指出位置与下一批主要敌型；标签不被树叶遮住，不与底栏相撞。
- [ ] 检查换位前后路线变化、封路拒绝、浅水限制、高台射程、唤醒、增援、技能即时释放；提示位置稳定且资源无误扣。
- [ ] 心被扣、伙伴睡着、露水不足与技能冷却分别有区别明确的局部反馈；色弱模式下不只看颜色。
- [ ] 暂停后仍能准确读格与做全部允许操作；帮助覆盖层不得造成战场误点。

### 状态与循环
- [ ] 星球任意旋转含背面/两极，标签与真实六角地块绑定；从背面候选聚焦后能清楚确认风险再进入。
- [ ] 单次选中只出现一张地点详情，不并排三张说明书；回星保留刚才的落点朝向并展示真实净化。
- [ ] 院中升级由真实场景物件进入；永久星砂/本局露水没有混用；未实现项无假按钮。
- [ ] 三选一/行商/局末界面有不同目的与内容层级，且一次确认只结算一次。

### 必须录的短验证片段
1. 七人布阵：拿起非水属性灯芯→查看合法格→浅水非法→取消→合法部署。
2. 从三侧来浊：开战→暂停→换位改变路线→封路失败→唤醒/增援→Q即时技能。
3. 胜后：净化→真实奖励→回到同一星球落点→另一背面候选聚焦。
4. 小院：点现有升级→费用/永久效果→取消→替换第三位起始伙伴→开始新局。
